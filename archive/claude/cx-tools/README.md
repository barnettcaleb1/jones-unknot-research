# cx-tools: certifying candidate counterexamples to the Jones unknot conjecture

Small, validated toolkit.  Pure-Python exact Kauffman bracket / Jones polynomial
(`bracket.py`), PD-code builders (`twist.py`), and a certificate script
(`certify.py`) that adds Alexander polynomial, signature, knot Floer homology
and hyperbolic geometry through snappy / spherogram / knot_floer_homology.

What is validated and what is not is recorded in `VALIDATION.md` (generated by
`validate.py`) and `TIMING.md` (generated by `speed_driver.py`).

## Setup

```
cd cx-tools
./venv/bin/python validate.py        # ~1 min, rewrites VALIDATION.md
./venv/bin/python speed_driver.py    # ~3 min, rewrites TIMING.md
```

The venv was created with Homebrew python 3.13.7 and holds snappy 3.3.2,
spherogram 2.4.1, knot_floer_homology 1.2.2 and sympy 1.14.0 (sympy is
installed but not needed by the toolkit).  `bracket.py` and `twist.py` need
nothing outside the standard library.

## Conventions (all pinned by VALIDATION.md)

* PD code: crossing `[a, b, c, d]` lists the four edge labels counterclockwise
  starting from the incoming under-edge (KnotInfo / Knot Atlas / spherogram).
  Labels may be any hashable objects; each appears exactly twice.  0-based
  (spherogram) and 1-based (Knot Atlas) labels both work.
* Bracket: `<X> = A <X_A> + A^-1 <X_B>`, `<O> = 1`, `delta = -A^2 - A^-2`;
  for `[a,b,c,d]` the A-smoothing joins (a,b),(c,d).
* Sign of crossing `[a,b,c,d]` is +1 iff the over strand runs d -> b.
* `V(t) = (-A^3)^(-w) <D>`, `t = A^-4`.  With this the closure of the braid
  `s1^3` (positive crossings) has `V = t + t^3 - t^4` (KnotInfo's 3_1); the
  Knot Atlas PD of 3_1 is the mirror and gives `-t^-4 + t^-3 + t^-1`.
* **Jones polynomials are dicts whose integer keys are exponents of t^(1/2)**:
  `{k: c}` means `sum c * t^(k/2)`.  Knots have even keys only;
  `jones_t(V)` converts to plain powers of t; `jones_str(V)` pretty-prints.
* Link orientation: read from the under-crossings (a -> c); a component that
  never goes under uses the edge numbering, else an arbitrary orientation with
  a warning (this only affects V of a link by a unit).
* Signature (certify.py): right-handed trefoil = -2.

## bracket.py

```python
from bracket import jones_from_pd, jones_str, jones_t, kauffman_bracket, Diagram
pd = [[1,4,2,5],[3,6,4,1],[5,2,6,3]]          # Knot Atlas 3_1
V = jones_from_pd(pd)                          # {-8: -1, -6: 1, -2: 1}
jones_str(V)                                   # '-t^-4 + t^-3 + t^-1'
jones_t(V)                                     # {-4: -1, -3: 1, -1: 1}
kauffman_bracket(pd)                           # {-5: -1, 3: -1, 7: 1}  (Laurent poly in A)
D = Diagram(pd); D.writhe(), D.num_components(), D.signs(), D.faces()
```

Command line: `./venv/bin/python bracket.py file.json` (JSON list of crossings
or `{"pd": [...]}`) or `bracket.py --pd '[[1,4,2,5],[3,6,4,1],[5,2,6,3]]'`.
Prints `<D>`, `V`, whether `V == 1`, and the contraction statistics.

Algorithm: planar-algebra contraction.  Crossings are absorbed one at a time
in a greedy order (every starting crossing is tried, the order with the
smallest maximum boundary width wins); a state is a perfect matching of the
open edges, carrying a Laurent polynomial stored as one big Python integer
(Kronecker substitution, exact).  Cost is governed by the boundary width
`w`, roughly `Catalan(w/2)` states per step: width 20 (about 17 000 states)
is the practical ceiling for a one-minute run.  `kauffman_bracket_naive(pd)`
is the 2^n state sum, for cross-checking small diagrams.

## certify.py

```python
from certify import certify
res = certify(pd)       # dict, see the module docstring for every key
res["V_str"], res["V_is_one"], res["det"], res["arf"]
res["alexander_str"], res["signature"], res["det_seifert"]
res["hfk"]["total_rank"], res["hfk"]["seifert_genus"], res["hfk_nontrivial"]
res["volume"], res["identify"], res["group"], res["group_is_Z"]
res["verdict"]
```

Command line: `./venv/bin/python certify.py file.json` where the file is a PD
code, `{"pd": [...]}`, `{"braid_closure": [1,1,1]}`, or
`{"plat_closure": [2,2,2], "n_strands": 4}`.  Output is JSON.

Logic of the verdict for a knot: `V != 1` -> not a candidate.  `V == 1` and
HFK total rank > 1 -> nontrivial knot with trivial Jones polynomial (a
counterexample; recheck everything).  `V == 1` and HFK rank 1 -> the unknot.
HFK-hat detects the unknot, so rank > 1 is a genuine certificate of
nontriviality; `identify()` returning `[]` and `group_is_Z == False` are NOT
certificates of anything (the SnapPea group simplification is heuristic).
`det = |V(-1)|` is cross-checked against `|det(S + S^T)|` from spherogram's
Seifert matrix, and the Seifert-matrix Alexander polynomial against the
graded Euler characteristic of HFK.

## twist.py

```python
from twist import braid_closure_pd, plat_closure_pd, insert_full_twists, clasp_unknot_pd, parallel_edge_pairs, connected_sum_pd
braid_closure_pd([1, 1, 1])             # 3_1, V = t + t^3 - t^4
braid_closure_pd([1, -2, 1, -2])        # 4_1
plat_closure_pd([2]*5 + [-1, 2], 4)     # twist knot C(5,2) = 7_2 (4-plat s2^5 s1^-1 s2)
pd = clasp_unknot_pd()                  # [[1,3,2,2],[3,1,4,4]], the clasp unknot, band edges 2 and 4
insert_full_twists(pd, 2, 4, -1)        # 3_1      (n = -1, -2, -3 -> 3_1, 5_2, 7_2)
insert_full_twists(pd, 2, 4, +2)        # 6_1      (n = +1, +2, +3 -> 4_1, 6_1, 8_1)
parallel_edge_pairs(pd)                 # every (e1, e2, face) site where twists can be inserted
connected_sum_pd(pd1, pd2)              # knots only
```

Braid words: `+i` = sigma_i (strand i passes over strand i+1, positive
crossing when all strands run upward), `-i` = its inverse.  Twist handedness:
`n > 0` inserts sigma-type crossings (the strand entering the twist box at its
bottom-left passes over), `n < 0` the inverse type; the sign of the resulting
crossings depends on whether the two strands are parallel or antiparallel.

Command line: `twist.py --braid '[1,1,1]'`, `twist.py --plat '[2,2,2]' 4`.

## Known limitations

* Boundary width above ~20 makes the contraction slow (state count grows like
  Catalan numbers); the greedy order is a heuristic.
* HFK is available for knots only; spherogram's `jones_polynomial`,
  `alexander_polynomial`, `signature`, `determinant` need Sage and were not
  usable here, which is why those invariants are computed independently.
* The Knot Atlas Jones polynomials were fetched on 2026-11-03; KnotInfo was
  not reachable from this machine, so the signature sign convention relies on
  spherogram's documented convention ("positive knots have negative
  signature").
